# 06 · ourApp 交互设计（分类 · 规格 · 优先级）

> 配套：[05-系统设计](05-系统设计.md)（对象、文件、同步）。
> 这份文档只回答三个问题：**这些功能分几类、每一类怎么做、先做哪个。**

---

## 0. 先说结论：14 个需求，其实只有 5 层

你列的东西看着多，但绝大部分不是"新功能"，而是**同一套几何引擎上的不同手势**。
把层级分对，加功能就是往对应层里填，不会牵连别的层。

| 层 | 管什么 | 包含 | 依赖 | 返工成本 |
|---|---|---|---|---|
| **L1 时间几何** | 时间 ↔ 像素的唯一换算 | 7 级缩放、吸附、刻度、当前时刻、Shift 横滚、LOD | 无 | **极高**（做错，上面全部重写） |
| **L2 任务编辑** | 单张卡的增删改 | 新建（+）、拖动、拖尾改时长、子任务 pin | L1 | 高 |
| **L3 选择与批量** | 多张卡一起动 | 框选、Ctrl 点选、批量 pin / 参与者 / 颜色 | L2 | 中 |
| **L4 结构操作** | 组与组之间 | 组排序、组 pin、折叠、复制粘贴 | L2 + L3 | 中 |
| **L5 视觉编码** | 颜色、明暗、辅助线 | 卡片配色、拖动聚焦、对齐参考线、折叠线 | L1 | 低（可后加） |

**颜色属于 L5**——它不改变任何行为，只改渲染。所以它可以最后做，也应该最后做：等交互稳定了再配色板，否则改一次颜色要动一次选择框、拖拽层、打印样式。

## 1. L1 · 时间刻度体系

### 1.1 七级刻度（一套规则，无例外）

视口宽度按 1200px 估算。

| 级 | 视口跨度 | px / 天 | 主刻度 | 次刻度（网格线） | 标签示例 | 吸附步长 | 最小显示时长 |
|---|---|---|---|---|---|---|---|
| L0 年 | 12 月 | 3.3 | 季度 | 月 | `2026` · `1 2 3` | 月 | 1 月 |
| L1 半年 | 6 月 | 6.6 | 月 | 半月（1/16） | `1月 2月` | 半月 | 半月 |
| L2 季 | 3 月 | 13 | 月 | 周（周一） | `3月` | 周 | 1 周 |
| L3 月 | 1 月 | 40 | 周 | 日 | `3月` · `1 8 15 22` | 日 | 2.5 天 |
| L4 半月 | 15 天 | 80 | 周 | 日 | `3/1 3/8` | 日 | 1.25 天 |
| L5 周 | 7 天 | 171 | 日 | 6 小时 | `周一 3/1` | 6 小时 | 14 小时 |
| L6 日 | 1 天 | 1200 | 6 小时 | 1 小时 | `08:00` | 1 小时 | 2 小时 |

**最小显示时长 = 视口跨度 ÷ 12**，一条规则管到底：
年视图 12 月 ÷12 = 1 月 → 正好是你要的"年级视图不显示不满一月的任务"。
你原来说的"差 4 级不显示"，实际效果就是这条，但用时长算比用级差算稳定（改视口宽度不会跳变）。

例外：**被选中、正在编辑、被搜索命中的任务始终显示**，否则选中之后它会消失。

### 1.2 缩放

- 触发：时间线区域内 `Ctrl + 滚轮`（Mac 上是 `⌘`）。
- 行为：级 ±1，**锚点 = 鼠标下的那个时刻**（缩放前后这个时刻的横坐标不动）。
- 边界：L0–L6 夹紧；80ms 节流；缩放时不触发选择、不打断拖拽（拖拽中禁止缩放）。
- 反馈：刻度淡入淡出（120ms），任务条重算宽度，吸附网格跟着换。

### 1.3 滚动

- `滚轮` → 时间线内部纵向滚动（组多的时候）。滚到边界后**允许穿透**到页面整体滚动，用 `overscroll-behavior: auto`。
- `Shift + 滚轮` → 横向滚时间轴。
- 触控板：`deltaX` 直接横滚，`deltaY` 纵滚，不强制 Shift。

### 1.4 当前时刻

- 一条 1px 竖线，颜色比验收虚线细、比网格明显（建议 `#C0392B` 30% 透明）。
- 位置 = 今天（含小时），不吸附。
- 设置面板里可关（默认开），开关存**视图态**，不同步。
- 视口里看不到"现在"时，时间轴右上角显示一个"回到现在"的小按钮。

### 1.5 设置面板

一个齿轮按钮，打开后只有四项，别做成设置中心：

| 项 | 默认 | 存在哪 |
|---|---|---|
| 显示当前时刻 | 开 | 视图态 |
| 拖动时吸附 | 开 | 视图态 |
| 拖动时聚焦变暗 | 开 | 视图态 |
| 颜色模式 | 按主线 | 视图态 |

## 2. L2 · 任务编辑

### 2.1 新建子任务

- 触发：鼠标悬停在**任务组那一行**时，组头右侧出现 `+`。
- 行为：在组内新建，起点 = 鼠标所指时间的吸附值（不在组内则取组尾），长度 = **1 个吸附步长**，lane = 第一条能放下的空行。
- 反馈：新卡直接进入"未 pin + 选中"状态，名称可原地编辑，`Esc` 放弃、`Enter` 确认。
- 边界：吸附步长为"日"及更细时，默认长度取 1 天，避免建出 1 小时的卡看不见。

### 2.2 拖动（未 pin 的子任务）

- 启动：`左键按住 250ms` 后进入拖拽（不是一按就走，避免误触）。
- 横向：跟手，松手吸附到当前级别的刻度。
- 纵向：跨 lane 移动；移出组的行数范围时，**组的高度自动增减**（向下加一行 / 向上加一行并把整组下移）。
- 反馈：见 3.3 的聚焦与参考线。
- 边界：拖到另一组上方时**不换组**（换组用剪切粘贴，见 4.3），避免误操作把任务挪走。

### 2.3 改时长（拖尾）

- 抓右边缘 8px 热区，`cursor: ew-resize`。
- 终点吸附；起点不动；时长不得小于 1 个吸附步长。
- 反向拖（拖过起点）→ 交换起止，不出现负时长。

### 2.4 pin / unpin（子任务）

- 悬停出现图钉：`📌` 斜放 = 未锁，横放 = 已锁。
- 点击切换。**pin 的语言**：锁时间、锁顺序，不锁行（见 05 的 I3）。
- 已 pin 的卡：拖拽和拖尾全部禁用，鼠标变成 `not-allowed`，但仍可被框选、仍可改参与者/颜色。
- 批量：多选后一次切换全部。

### 2.5 删除

- 卡上右键菜单 / 选中后 `Delete`。
- 删除进撤销栈；readme 文件不删（移到 `.trash/`），防止误删文档。

## 3. L1+L5 · 拖动时的视觉

### 3.1 吸附

- 吸附在**模型层**算（05 的 I4），UI 只显示结果。
- 吸附关闭时（设置里），拖动为连续值，但松手仍对齐到分钟，避免亚像素脏数据。

### 3.2 对齐参考线

拖动时在时间轴**上下两端**各画一条竖参考线：

- 左线 = 候选起点，右线 = 候选终点。
- 两端各挂一个刻度标签，格式随级别：

| 级别 | 标签格式 | 附注 |
|---|---|---|
| L0–L1 | `2027-03` | 只到月 |
| L2–L4 | `03-08` | 月-日 |
| L5–L6 | `03-08 14:00` | 到小时 |

- 同时在中部显示一句"时长：2 个月 3 天"（人读的），随拖动实时更新。
- 对齐到别的任务边界时，参考线变实线并高亮（磁吸提示）。

### 3.3 聚焦变暗

- 拖动开始：除被拖任务和它所在的组外，其余全部 `opacity: .35`，并去掉饱和度（`filter: grayscale(.35)`）。
- 被拖的卡：提升 `z-index`、加投影、轻微放大（`scale 1.02`）。
- 松手 160ms 后恢复。
- 变暗用 opacity 而不是换色，保证颜色语义不丢。

## 4. L3 / L4 · 选择、批量、结构

### 4.1 选择

- `Ctrl + 拖框` → 框选（只在空白处起手，避免和拖动冲突）。
- `Ctrl + 左键` → 增减单张。
- `Esc` 清空；点空白处清空。
- 选择是**会话态**，不进文件、不同步。

### 4.2 批量面板

- 选中 ≥1 时，在选区上方浮出一个小面板：`[📌 锁] [🔓 解]  [参与者 ▾]  [颜色 ▾]`。
- **面板不因为点了一个动作就关**——这是你特别强调的：先设 pin，再设参与者，中间不存在"重来一次"。
- 参与者展开后是 4 个圆点，点一下 = 给**所有选中任务**加/减这个人；圆点本身显示三态：全选（实心）、部分（半实心）、未选（空心）。
- 关闭：`Esc` 或点面板外。

### 4.3 复制粘贴

- `Ctrl+C` 复制选中集合 S。
- `Ctrl+V` 粘到"当前鼠标所在的组"。

算法（相对位置不能丢）：

```
锚点 T0 = 鼠标位置吸附到刻度
基准 minStart = S 里最早的 start，minLane = S 里最靠上的 lane
每个任务：Δt = start - minStart，Δlane = lane - minLane
粘贴后：start = T0 + Δt，lane = 目标组里从底部开始按 Δlane 依次找空行
```

- 新 id、新 rev；**继承**：名称、时长、颜色、组归属；**不继承**：pin（新任务一律未锁）、参与者（人各有责）。
- 粘完跑一次 lane 压缩。
- 若目标组放不下（行数不够），自动加行——但只在粘贴时加，不在拖动时加。

### 4.4 主任务（组）

| 操作 | 触发 | 规则 |
|---|---|---|
| 排序 | 悬停组头出现 `▲▼` | 只在组 **unpin** 时可用；一次挪一整组，组内顺序不变 |
| pin | 组头图钉 | 锁的是**排序**，不是内容；已 pin 的组不能被别人排到前面 |
| 折叠 | 悬停最左侧出现 `〉` | 折叠成一条 3px 高的色带；悬停变粗到 8px 并显示组名；点击展开 |

- 折叠状态存**视图态**（本地），不同步——每个人可以自己收起不想看的线。
- 折叠不影响：数据、参与、验收统计。只是画法不同。

### 4.5 空行压缩（最容易做错的一条）

```
每次提交前：normalizeLanes(group)
  1. 取该组所有任务，按 (lane, order) 排序
  2. 从 0 开始重新编号，跳过空 lane
  3. 不改变任务的相对上下关系
```

- **优先级**：压缩 > pin。pin 只管时间，不管行（05 的 I3）。
- 但压缩必须**保序**：被 pin 的任务在压缩后仍在原来那批任务的上/下方。
- 压缩是纯函数，不产生 diff 之外的副作用——否则撤销会错位。

## 5. L5 · 颜色系统

> 完整的一套（主题色、语义色、深色模式、投影/打印）在 [07-配色系统](07-配色系统.md)。
> 这一节只管**卡片色**——也就是用户在时间线上能改的那部分。

这条要单独说，因为自由配色是最容易把界面做脏的地方。

### 5.1 先定颜色的语义

**颜色是标签，不是状态。**

| 信息 | 用什么编码 | 为什么 |
|---|---|---|
| 属于哪条主线 | 组色条（左侧 3px 高饱和） | 已有，稳定 |
| 是否锁定 | 图钉图标 | 图标比颜色可靠，色盲也能懂 |
| 谁参与 | 头像圆点 | 已有 |
| 这是"哪一类活" | **卡片底色** | 唯一留给用户的自由维度 |

只要颜色只表示"我给它归了个类"，就不会和 pin、负责人、主线打架。

### 5.2 两层明度，别混

- **主线色**：高饱和，只用 3px 细条 —— 像书脊。
- **卡片色**：低饱和浅底，铺满整张卡 —— 像便签。

两者不在同一个明度层，所以"紫卡片"不会被误读成"属于紫色那条线"。

### 5.3 色板：给 token，不给取色器

```js
COLORS = [
  { id:'auto', name:'跟随主线', bg:'#FFFFFF', fg:'#23262B' },
  { id:'c1', name:'琥珀', bg:'#FBF0DE', bar:'#B5762A' },
  { id:'c2', name:'青',   bg:'#E7F0EE', bar:'#2E6F6A' },
  { id:'c3', name:'紫',   bg:'#EFEAF5', bar:'#6B5B95' },
  { id:'c4', name:'蓝',   bg:'#E7EEF5', bar:'#3C6E9F' },
  { id:'c5', name:'橄榄', bg:'#EDF1E6', bar:'#5E7C4A' },
  { id:'c6', name:'玫瑰', bg:'#F8E9E9', bar:'#A95555' },
  { id:'c7', name:'沙',   bg:'#F3EFE6', bar:'#9A7B4F' },
  { id:'c8', name:'灰',   bg:'#EDEDEA', bar:'#7A7A72' },
]
```

三条理由：

1. **不做自由取色器**。自由取色必然产出低对比度、刺眼、打印发灰的颜色，而且没法做深色模式。
2. **存 token 不存 hex**（`color: "c3"`）。换主题、调色板、做深色模式时只改一处，不用迁移数据。
3. **颜色是模型态**，随任务同步；在 `tasks/{id}.json` 里加一行 `color`。

### 5.4 可访问性

- 所有底色 + 深色文字，对比度 ≥ 4.5:1（上面这批都过）。
- 颜色永远不是唯一编码：卡上还有 id、图钉、头像点、组色条。
- 提供"色盲友好"开关：开启后每张带色卡右上角多一个小三角标记（pattern 冗余）。
- 打印：浅底 + 深色左条，灰度下靠明度差区分（≥15%），不靠色相。

### 5.5 交互

- 单卡：右键菜单 / 详情面板里的色板。
- 批量：多选后 `[颜色 ▾]`，一次刷全部。
- `auto` 必须存在且是默认——不然所有人第一天都在纠结选什么色。

## 6. 优先级

排序原则三条：**返工成本** > **依赖关系** > **单次使用价值**。
一个功能再爽，如果它建立在会变的地基上，就先别做。

### P0 · 地基（不做完，后面全是返工）

| # | 内容 | 为什么是 P0 |
|---|---|---|
| 1 | 对象模型：Group / Task / Duty / Deliverable | 决定了所有文件与同步 |
| 2 | 几何引擎：px ↔ 时间、7 级刻度、吸附、LOD | 所有交互都调它；写错要重写每个手势 |
| 3 | Command + UndoStack | 复杂交互没有撤销等于不能用，且后补成本极高 |
| 4 | lane 分配与压缩（纯函数） | 直接决定"组会不会无限变高" |
| 5 | 视图态 / 模型态分离 | 混在一起，同步一上来就出错 |

### P1 · 一个人能天天用（v0.2）

拖动 · 拖尾改时长 · 吸附 · 对齐参考线 · 聚焦变暗 · 子任务 pin · 组的折叠/展开 · 新建/删除 · Ctrl 缩放 · Shift 横滚 · 当前时刻 · 设置面板 · 单卡颜色

### P2 · 效率（v0.3）

框选/多选 · 批量 pin · 批量参与者 · 批量颜色 · 复制粘贴 · 组排序 · 组 pin · LOD 细化

### P3 · 协作（v0.4）

同步协议 · 冲突 UI · 聊天（或替代为"自动摘要进 log"）· 邮箱推送

> 注意 P3 里"聊天"排在最后不是不重要，是它**可以被替代**：5.1 里那行"人读的摘要"本来就能当留痕用。
> 先做同步、后做聊天，聊天对象就只是一个渲染器，不承担数据一致性责任。

## 7. 迭代计划（每轮都要能演示）

| 迭代 | 目标 | 验收 | 大致工期 |
|---|---|---|---|
| **1** | 换地基，界面看起来没变 | 现有 4 个交互全跑在新模型上；拖动已经吸附；Ctrl+Z 能用 | 3–5 天 |
| **2** | 时间线可编辑 | 一个人能完整建一条主线 + 5 个子任务，拖、缩、pin、折叠、改色，全程不刷新 | 1 周 |
| **3** | 批量与结构 | 框选 5 张一次 pin + 加人；复制一组粘到另一组，相对位置不变 | 1 周 |
| **4** | 同步 | 两台机器，A 拖一下，B 3 秒内看到；两人同拖一张，B 收到冲突提示 | 1–2 周 |

迭代 1 的验收标准故意写得像"没有新功能"——**地基迭代就该看起来没变化**，否则说明你在同时改地基和加功能，风险翻倍。

## 8. 五个一定会踩的坑

1. **拖拽状态和 React 渲染打架**。拖动每帧都在改位置，别直接 setState 到模型；用一份 `dragPreview` 会话态，放手才 commit。否则一卡一卡的。
2. **吸附在渲染层做**。做完你会发现：拖动时对齐了，松手又偏了，因为模型存的是原始值。必须是模型层吸附。
3. **复制粘贴按像素算偏移**。换个缩放级别就错位。必须按"时间差 + 行差"。
4. **折叠和参与列表脱节**。折叠只是不画，数据还在；负责域里该有的任务不能少。
5. **颜色做成自由取色**。三个月后整块看板会变成一锅粥，而且深色模式没法做。

## 9. 还是需要你拍板

1. 折叠状态：**本地**（各看各的）还是**同步**（全组一致）？我建议本地。
2. 复制粘贴是否跨项目？（现在只有一个项目，先假设不跨。）
3. 组的排序是否允许"插队"到已 pin 的组前面？建议不允许，pin 就是秩序。
4. 颜色语义要不要预设含义（比如"黄 = 卡住了，红 = 有风险"）？建议不要，留给每个人自己用，否则第二个人就理解错。
