# 01 讲义：从一粒沙子到一台计算机——树莓派到底是个什么东西

> **这一讲的目的不是科普。**
> 是让三个没写过代码的同学，在明天结束时能回答一个问题：*我们做的这个东西，为什么长这样。*
> 只有他们理解了"单片机 ≠ 小电脑"，后面的分工才不会变成"你去焊板子、我去写代码"这种把项目做死的分法。

- **时长**：45 分钟（讲 30，停 10，实物 5）
- **要准备**：树莓派插好电、一个单片机（ESP32 或 Arduino 都行）、一块舵机、一张打印的 [图1](../assets/图1-计算谱系.png)
- **节奏**：每讲 10 分钟停一次，问一个能用"是/不是"回答的问题。气氛比准确重要，准确可以事后补。

---

## 最短版：只用 8 分钟（其余全砍）

> 如果你觉得下面太长——大概率是对的。明天就只讲这一页，其余全部删掉。

不讲历史，不讲 MMU，不讲开机流程。只做三件事，全程用实物：

1. 桌上摆两个东西：**树莓派**（插着电、开着机）+ **一块单片机**（ESP32 或 Arduino 都行）。
   说一句：“这两个都能做我们这个项目。”
2. **演示**：树莓派接屏幕，打开终端敲一行命令，屏幕上出字；单片机插上电，只有一个小灯在闪。
   说一句：“一个是电脑，一个不是。”
3. 收尾一句话：**“会想的部分交给树莓派，会动的部分交给单片机。”**
   然后直接翻到认领表，让他们选。

历史、分层、MMU 全部删掉。以后谁问，把附 A 的名词表发给他。

## 0. 开场：先给结论（3 分钟）

【讲】

> 今天讲的东西听起来离我们很远，但我保证它是明天分工的地基。
>
> 先说三句话，剩下的时间都是在解释这三句话：
>
> **第一，我们做的不是"一个会说话的音箱"，是一个"有身体的学伴"。** 差别在于：音箱只有嘴，我们有手、有眼、有表情。
>
> **第二，这个身体由两种完全不同的东西组成。** 一颗"大脑"——树莓派，它其实是一台完整的微型计算机；和几块"肌肉"——单片机、舵机、灯——它们只负责动。
>
> **第三，大脑和肌肉的干活方式完全不一样。** 不是快慢的区别，是逻辑的区别。理解了这一点，你就知道自己想干哪一块。

【停】问一句："在座各位，谁觉得自己以后想做硬件？做软件？"——不用回答，举手就行。这一举手，明天分工就有底了。

## 1. 一切从"开关"开始（8 分钟）

【讲】

> 计算机的本质，是用开关搭逻辑。
>
> 一个开关有两种状态：通、断。两个开关串起来是"与"，并起来是"或"，再加一个反着来的，就是"非"。用这三种东西，能搭出加法器；加法器加寄存器加控制器，就是 CPU。
>
> 所以计算机不是什么神秘的东西，它是**几十亿个极其可靠的开关，按设计好的方式连起来**。

时间线，四行就够，别展开：

| 年份 | 事 | 为什么重要 |
|---|---|---|
| 1947 | 贝尔实验室做出第一个晶体管 | 用一小块半导体代替真空管，开关变小、变冷、变可靠 |
| 1954–1959 | 硅晶体管 → 集成电路 | 不再一个个焊，直接在一个硅片上"印"出来 |
| 1965 | 摩尔定律 | 同样价钱，每两年翻一倍。这句话管了后面五十年 |
| 1971 | Intel 4004，2300 个晶体管 | 第一次把"计算机的大脑"做成一片能买到的芯片 |

给一个数量感，让他们"哇"一下：

> 1971 年的 4004 有 2300 个晶体管。今天的旗舰手机芯片，是接近 200 亿个。
>
> 五十年，八百多万倍。同一块指甲盖大小的硅片，当年是一台机器的心脏，现在是一颗随手扔在抽屉里的零件。

### 1.1 为什么是通信行业先把它推起来（这是重点，别跳过）

【讲】

> 有个细节很有意思：晶体管不是为计算机发明的，是为**电话**发明的。
>
> 打长途电话，信号会衰减，中间要放大。当时的放大器用真空管，又大又热，还老坏。贝尔实验室是电话公司的实验室，它要解决的是"怎么把声音放得更大更可靠"，于是做出了晶体管。
>
> 同一时期还有雷达、无线电、火炮控制——都是二战和冷战的需求。
>
> 所以顺序是：**通信和军事孕育了半导体，计算机把它养大了。**
>
> 反过来呢？器件便宜了，计算机才从"算不算得起"变成"人人都能有一台"。信息学——操作系统、编译原理、算法——才有意义。你没法在只有 1KB 内存的机器上讨论虚拟内存。

这句话可以留着，答辩也用得上：**"半导体的进步，第一次让'计算'变成了一种可以随便浪费的资源。"**

## 2. 一张地图：从器件到应用（7 分钟）

【讲】

> 接下来这张图，我希望你们记住形状，不用记住字。
>
> 从下往上：**器件（晶体管）→ 门电路 → 微架构（CPU 怎么排）→ 指令集（机器认识哪些命令）→ 操作系统 → 应用**。
>
> 每一层都在隐藏下一层的复杂度。你写 `print("hello")` 的时候，下面有几十层东西在替你干活：解释器、系统调用、驱动、内存管理、CPU 里的流水线、最后是几十亿个开关在翻转。
>
> 这就是"会用电脑"和"懂计算机"的区别。会用，是站在最上面一层；懂，是知道下面还有几层。

【停】问："那你们觉得，我们做这个项目，主要站在哪一层？"——答案：最上面两层（应用 + 一点系统）。这句很重要，它决定了工作量。

## 3. 谱系：不是一条性能线，是两种设计哲学（12 分钟）

这一节是全场核心。配合 [图1](../assets/图1-计算谱系.png) 讲。

【讲】

> 大家脑子里可能有一条线：单片机很弱，树莓派中等，电脑很强。**这条线是错的。**
>
> 真实情况是两条不同的轴：
>
> 一条是**通用性**——能不能装各种软件、接各种设备、跑各种语言。往上走。
> 一条是**确定性**——我让它 20 毫秒后动一下，它是不是真的 20 毫秒后动。往下走。
>
> 单片机和树莓派，是这两条轴上的两个不同选择，不是一个强一个弱。

| | 微控制器（MCU） | 单板计算机（SBC，树莓派） | 个人计算机 / 服务器 |
|---|---|---|---|
| 例子 | 8051、AVR、STM32、ESP32 | 树莓派、香橙派 | 你的笔记本、实验室服务器 |
| 内存 | KB 级（ESP32-S3 是 512 KB） | GB 级 | GB–TB 级 |
| 操作系统 | 没有，或 FreeRTOS（任务调度器） | 完整 Linux | 完整 Linux/Windows |
| 开机 | 毫秒级 | 20–40 秒 | 十几秒到几分钟 |
| 功耗 | 毫瓦级 | 几瓦 | 几十到几百瓦 |
| 你写的程序 | **就是整个设备的行为** | 系统里的一个进程 | 系统里的一个进程 |
| 实时性 | 微秒级、可预测 | 毫秒级、不可预测 | 更差 |
| 开发语言 | C / C++ / 汇编 | Python / C++ / 什么都有 | 同左 |

### 3.1 分水岭不是性能，是"有没有 MMU"

【讲】

> 有一个词今天只需要记住：**MMU**，内存管理单元。
>
> 它的作用是给每个程序一个"假地址"，再由硬件翻译成真地址。有了它，两个程序才能各占一块内存互不打架，一个程序崩了系统还能活着——这叫进程隔离。没有它，所有程序共享同一片内存，谁写错一个指针，整台机器就死了。
>
> **Linux 需要 MMU 才能跑。** 所以：
>
> - ESP32-S3 **没有**支撑虚拟内存的 MMU（它只有给外部 Flash/PSRAM 做地址映射的那种），所以它跑不了 Linux，只能跑 FreeRTOS。
> - 树莓派有 MMU，所以它能跑完整的 Linux，能装 `apt`，能开 ssh，能同时跑十个 Python 脚本。
>
> 这不是"性能不够"。这是**缺一个部件**。你给它再多内存再多主频，它还是跑不了 Linux。
>
> （冷知识：工程上确实有给无 MMU 芯片用的 uClinux，但那是另一套生态，不是我们要走的路。）

### 3.2 两种完全不同的"使用逻辑"

这一段是用户最想讲清楚的，用比喻，别用术语。

【讲】

> 我用两个东西打比方。
>
> **单片机像一把剃须刀。** 你拆开它，里面有一块小板子。你为它写程序，是设计"这个物件怎么动"——什么时候转、转多快、电池没电了怎么办。程序烧进去，上电就干活，没有登录、没有桌面、没有"安装软件"。你面对的是**一根引脚、一个定时器、一个中断**。
>
> **树莓派像一台个人电脑。** 它开机要先进系统，你要连网、要 `sudo apt install`、要管用户名密码、要看日志、要防止 SD 卡坏掉。你为它写程序，是写"系统里的一个软件"，不是设计"这一整台机器"。
>
> 这就是 IBM 在 1981 年提出的那个概念：个人计算机——**一台通用的、你可以往里装任何东西的机器**。树莓派继承的是这个血统，不是单片机的血统。
>
> 底子上，两个都是海量的晶体管，都能做控制，都可编程。但**宏观体感差得非常远**，而且这个差异不是性能带来的。

【停】问："那既然树莓派什么都能干，为什么还要单片机？"——留 10 秒，然后自己答：

> 因为**确定性**。你让树莓派每 20 毫秒精确地给舵机一个脉冲，Linux 会说"我尽力"。它可能在处理网络包、可能在写 SD 卡、可能在跑垃圾回收，你的 20 毫秒就变成了 23 毫秒。舵机就抖。
>
> 而在单片机上，你可以做到微秒级，而且你知道它一定准时。
>
> **所以：思考归电脑，身体归单片机。** 这句话是我们这个项目架构的根。

## 4. 树莓派到底是什么（10 分钟）

【讲】

> 2012 年，剑桥的一群人做了块 35 美元的小板子，最初目的是"让每个孩子都能学编程"。
>
> 但它意外地变成了一台完整的计算机：一颗 SoC（CPU + GPU 在一块硅片上）、内存、用 SD 卡当硬盘、USB、HDMI、有线网、WiFi，外加一排 40 个针脚。
>
> 那排针脚叫 GPIO。**注意：它不是"单片机的引脚"。** 它是一台 Linux 机器上被"暴露出来"的几根线，你要通过内核驱动去操作它（`/dev/gpiochip`、sysfs、`libgpiod`、`gpiozero`）。这个区别，就是"用电脑"和"用单片机"的区别。

### 4.1 它开机的时候发生了什么（讲这个，他们才会有"这是一台电脑"的实感）

【讲】

> 上电 → 片上的一小段固件（bootloader）→ 加载 Linux 内核 → 内核认出所有硬件、挂上文件系统 → 启动 1 号进程（systemd）→ 启动一堆服务 → 启动你的程序。
>
> 这条链，和一台阿里云服务器一模一样。你实验室那台跑模型的机器，也是这条链。
>
> 所以**开机自启**这件事，对我们是个真问题：断电重启之后，机器人得自己站起来，不能等人 ssh 进去敲命令。这个后面是 E 线的活。

### 4.2 坑，提前打预防针（这一节能省掉后面一个月的 debug）

- **3.3V**：针脚是 3.3V，接 5V 的东西会烧。ESP32 是 3.3V，Arduino Uno 是 5V，别混。
- **每针只有十几毫安**：直接驱动舵机或大功率 LED 会掉压、重启。要用外部电源 + 驱动板。
- **没有模拟输入**：想读电位器、读电池电压，得外挂 ADC。
- **Linux 不实时**：上面讲过。
- **SD 卡会坏**：突然断电是最常见死法。养成 `sudo shutdown now` 的习惯，并且定期做镜像备份。
- **供电**：树莓派 5 要 5V/5A，树莓派 4 要 5V/3A。用手机充电器凑合，会在插上摄像头+WiFi 满载时随机重启，然后你会怀疑是代码问题，查三天。

【停】这里可以直接演示：把舵机接上 GPIO 直接供电，让它动，看树莓派重启。**一次现场翻车，比讲十遍都管用。**

## 5. 我们这个项目，落在地图的哪个位置（8 分钟）

【讲】

> 现在把我们的项目摊开，你看它落在哪。
>
> **语音链路**：麦克风 → 判断有没有人在说话 → 识别成文字 → 去知识库检索 → 大模型生成回答 → 合成语音 → 播放。这一整条，全是"计算机"的活：Python、网络、多进程、流式。没有一行是单片机的活。
>
> **身体**：舵机、灯、屏幕。这是"实时"的活，天然属于单片机那一侧。
>
> **视觉**：摄像头 → 找到教材那一页 → OCR → 结合上下文回答。这也是"计算机"的活，而且吃算力。
>
> 所以结论很清楚：**我们选树莓派当大脑，不是因为"性能强"，是因为我们的难点全在软件链路上。**
>
> 而且有个很实际的好处：这条链路可以**先在笔记本上调通，再原样搬到树莓派**。同一份 Python，同一个模型 API，换个机器就能跑。
>
> 如果反过来，用 ESP32-S3 当主控呢？同样一条链路，你得用 C 重写：TLS 握手、WebSocket、音频编解码、JSON 解析，全塞进 512KB 内存。我们四个人，三个没写过代码，这条路走不到年底。
>
> 申请书原文写的是"ESP32-S3 **或** 树莓派"。我们选了后者，没超范围。

## 6. 收尾：三个问题（3 分钟）

不用他们答对，答错才有得聊。

1. 为什么 ESP32-S3 跑不了 Linux？
   → 没有支撑虚拟内存的 MMU，不是性能问题。
2. 为什么舵机不直接接在树莓派的针脚上？
   → Linux 不实时 + 电流不够，会抖、会重启。
3. 如果明天让你选，你想做"大脑"还是"身体"？为什么？
   → 这题没有标准答案，但答案就是明天分工的起点。

## 附 A：名词表（发给他们，别在课上念）

| 词 | 一句话 |
|---|---|
| 半导体 | 导电性介于导体和绝缘体之间的材料，硅是其中最常用的一种 |
| 晶体管 | 用半导体做的小开关/放大器，现代计算机的基本单元 |
| 集成电路 / 芯片 | 把成千上万个晶体管做在同一块硅片上 |
| SoC | System on Chip，把 CPU、GPU、内存控制器等塞进一颗芯片 |
| MCU | 微控制器，一颗芯片里集成了 CPU + 内存 + 外设，通常不跑操作系统 |
| SBC | 单板计算机，一块板子就是一台完整电脑，树莓派是代表 |
| GPIO | 通用输入输出引脚，可以被程序控制高低电平 |
| I2C / SPI / UART | 三种常见的芯片间通信总线，接传感器/驱动板用 |
| PWM | 脉宽调制，用"开关的快慢"模拟"力度大小"，舵机、调光都用它 |
| MMU | 内存管理单元，做虚拟地址到物理地址的转换，进程隔离靠它 |
| RTOS | 实时操作系统，FreeRTOS 是最常见的一个，跑在单片机上 |
| VAD | Voice Activity Detection，判断"现在有没有人在说话" |
| ASR / TTS | 语音转文字 / 文字转语音 |
| RAG | 检索增强生成，先查资料再让大模型回答 |
| 端 / 云 | 端 = 手边这台设备；云 = 远处的服务器 |
