## 2. 每天怎么干：改 → 跑通 → 搬

### ① 改，只在自己的文件夹里

```bash
cd users/李美蓉

# 第一次：把公共工程复制一份进来（别复制 node_modules，太慢也没必要）
robocopy ..\..\tools\ourApp .\ourApp /E /XD node_modules
```

改坏了不影响任何人，随便试。

### ② 跑通

```bash
cd ourApp
pnpm install
pnpm dev          # 开发：http://localhost:5173
```

或者打成单文件，双击验一遍：

```bash
node build.mjs    # 生成 dist/ourApp.html
```

### ③ 搬回公共工程

确认能用了，把改动整体搬到 `proj/`：

```bash
robocopy .\ourApp ..\..\tools\ourApp /E /XD node_modules
```

搬之前在群里说一句：**「我改了 X，搬回 ourApp 了」**。


### ④ 什么时候该进 `proj/`

`proj/` 是**交付物展台**，不是工作区。只有「换台机器也能跑起来、你自己刚验过一遍、带 README」的东西才进得去。

| 你做的东西 | 放哪 |
|---|---|
| 改了工作台（ourApp）的界面/交互 | 搬回 `tools/ourApp/` |
| 机器人上的语音程序、BOM、3D 文件、评测集 | 搬进 `proj/` 对应目录 |
| 还没跑通的半成品 | 就留在你的 `试验/` |

搬进 `proj/` 之前，读一遍 [`proj/README.md`](../../proj/README.md)。

### 搬之前，这三条必须过

- [ ] `node cli.mjs check` 不报错
- [ ] `pnpm install && node build.mjs` 能过
- [ ] 双击 `dist/ourApp.html` 能打开，能拖、能撤销

## 3. 不要做的事

| 不要 | 为什么 |
|---|---|
| 直接改 `proj/` | 那是公共工程，别人也在跑 |
| 改别人的 `users/xxx/` | 那是别人的实验田 |
| 提交 `node_modules/` | 几万个文件，仓库会炸 |
| 把密码、API key 写进代码 | 所有人可见，而且会推到 GitHub |

## 4. 卡住了怎么问

不要问「这个怎么弄」。发三句话：

1. **我在做什么**：我想让时间线上的卡片能吸附
2. **卡在哪**：贴报错原文（整段，别截一半）
3. **我想问什么**：是环境问题，还是我代码写错了

三句话发出来，别人一分钟就能判断要不要接手。

## 5. 常用命令

```bash
# 看板数据（改的是 data/board.json）
node cli.mjs list                  # 所有任务
node cli.mjs who 4             # 我参与了什么
node cli.mjs task set A1 --start 2027-03-01 --end 2027-03-20
node cli.mjs duty A1 +4    # 把自己加进参与
node cli.mjs mark ls               # 验收节点
node cli.mjs check                 # 数据有没有坏

# 工程
pnpm dev                # 开发
node build.mjs          # 打包成 dist/ourApp.html
node make-data.mjs      # 从源码重新生成 data/board.json
```

> 你最近会用的一条：`node cli.mjs duty A1 +1 +4`
