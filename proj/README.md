# proj · 交付物

**这里只放「已经跑通、确认能用、可以直接拼进最终作品」的东西。**

`proj` 不是工作区，是展台。别在这里试错。

---

## 什么能进 proj

必须同时满足三条：

1. **跑得起来** —— 换一台机器，照着它自己的 README 能从零跑到能用
2. **自己验过** —— 不是"应该能跑"，是"我刚跑了一遍"
3. **带说明** —— 同目录下一份 README，写清楚：解决什么问题、怎么装、怎么跑、已知问题

进了 proj 的目录，就是**对外可以展示的技术内容**。

## 什么不能进 proj

| 不进 | 去哪 |
|---|---|
| ourApp 工作台 | `tools/ourApp/`（自己用的管理工具，不是交付物） |
| 半成品、试验代码 | `users/<你>/试验/` |
| 笔记、截图草稿 | `users/<你>/笔记/` |
| 会议记录、分工表 | `docs/` |
| 带个人信息的东西（申请表、名单） | 不要进仓库 |

---

## 目录约定（现在开始长）

```
proj/
├─ README.md          这份
├─ firmware/          树莓派上的程序（语音链路、状态机、服务）
├─ hardware/          BOM、接线图、3D 外壳文件
├─ vision/            页面检测 / OCR / 指读
├─ knowledge/         教材知识点、RAG 配置、评测集
└─ docs/              组装教程、部署脚本、演示材料
```

上面的目录**按需创建**，没有东西就先不建，别造空文件夹。

## 怎么把东西放进来

在自己工作区改好、验完，然后：

```bash
# 从你的工作区搬进 proj（只搬源码/文件，别搬 node_modules）
robocopy users\<你>\ourApp ..\..\proj\firmware /E /XD node_modules
```

搬之前在群里说一句：**「我把 X 搬进 proj 了，验过」**，并附一句你怎么验的。
